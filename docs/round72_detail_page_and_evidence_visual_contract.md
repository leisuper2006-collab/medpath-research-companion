# Round72 详情页与证据视觉硬约束

本文件把用户最新要求转化为下一轮建设的可检查标准：每一个最小单元，包括方法卡、图谱卡、文章Skill、开源工具卡、插件卡、3D小岛建筑和移动端入口，都必须拥有独立文案、独立示例、来源边界和产品级详情页叙事。不得用同一段模板文字批量替换名词。

## 1. 产品详情页标准

每个详情页采用“Apple式滚动叙事”组织，但不复制任何商业网站文本或视觉资产。页面应包含：

1. **Hero开场**：一句人话解释“这个方法解决什么问题”，不要先堆术语。
2. **新手场景**：用一个真实科研小白会遇到的问题切入，例如“我想做基因敲除，但不知道选CRISPR还是shRNA”。
3. **输入材料**：列出需要准备的数据、样本、文献、伦理材料和导师复核点。
4. **方法路线**：用步骤化时间线说明从0到1怎么做。
5. **示例图**：展示本地重绘示例图或合规公开数据生成图，不复制期刊原图。
6. **来源说明**：说明公开来源线索、PMID/数据库来源、复用边界和是否为合成教学数据。
7. **常见误区**：写出该方法最容易犯的3-5个错误。
8. **模型API请求窗**：允许用户描述自己的需求，由平台生成规范化Skill请求包。
9. **导师/教师复核清单**：明确哪些结论必须人工复核。
10. **下一步学习路径**：推荐相邻方法、文章类型、图表类型和工具。

## 2. 唯一性标准

每个最小单元必须在以下字段上体现真实差异：

- `hero_title` / `plot_product_title` / `article_product_title`
- 新手引导段落
- 适用场景与不适用场景
- 输入材料字段
- 推荐图表与推荐文章类型
- 示例图标题与图注
- 来源说明句
- 常见错误
- 用户需求窗口提示
- 导师复核问题

禁止出现“换几个词但结构完全相同”的批量段落。已有 `round31_content_uniqueness_audit.py` 继续作为基础检查，后续需要新增更严格的详情页相似度审计。

## 3. 示例图与来源标准

示例图必须分为三类标注：

1. **公开来源重绘图**：基于公开论文、公开数据库或公开教程的数据结构，用本地代码重绘，不复制原论文图片。
2. **合成教学图**：使用合成数据解释图形语法和字段关系，必须标注“不代表真实研究结果”。
3. **用户数据运行图**：用户上传或接入自己的数据后由平台生成，必须先通过数据字段审查、隐私审查和导师复核。

对于顶刊或1/2区来源，页面只写“来源线索”和可核验信息，例如论文题目、期刊、年份、PMID、数据库ID；不得截取或复刻受版权保护的原图作为本站资产。

## 4. 视觉设计参考

调研结论：

- Apple产品页常使用单一强Hero、充足留白、渐进式信息揭示和产品中心叙事；本项目应把“方法本身”作为产品，让用户逐屏理解它的用途、输入、产出和风险。
- Mobbin适合参考真实App的信息架构、卡片密度、详情页、筛选器、移动端导航和用户流，不直接复制商业UI。
- Awwwards的3D与互动网站可作为交互动效参考，但本项目的科研工具页必须保持信息可读，不做喧宾夺主的动效。
- 科研图表继续优先采用R/ggplot2或可复现代码生成，示例图要保留源数据、脚本和图注边界。

参考来源：

- Apple Developer Design: https://developer.apple.com/design/
- Mobbin: https://mobbin.com/
- Awwwards 3D websites: https://www.awwwards.com/websites/3d/
- Modern Statistics for Modern Biology, Data Visualization: https://www.huber.embl.de/msmb/03-chap.html
- Nature Methods Points of View data visualization guide: https://communities.springernature.com/posts/data-visualization-a-view-of-every-points-of-view-column
