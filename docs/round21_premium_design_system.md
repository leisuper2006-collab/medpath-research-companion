# Round21 高级视觉与交互规范：MedPath Research Companion

## 0. 文档定位

本规范用于指导 MedPath Research Companion 后续网页端、移动端 App、Figma 原型和 3D 科研小岛的高级视觉与交互升级。它不是前端实现说明，也不要求本轮改动任何前端代码。

核心目标：

- 把平台从“可打开的科研教育原型”提升为“可信、可学习、可演示、可持续扩展的科研伴侣产品”。
- 同时服务科研小白、研究生、教师、医学 AI 课程团队和方法库维护者。
- 将方法库、文章工作流、科研绘图室、数据审查、模型网关、3D 科研小岛和手机端 App 收敛到同一套视觉语言。
- 明确外部设计库只可借鉴产品模式、动效节奏和组件组织方式，不复制授权不明代码、模板、商业素材或论文原图。

## 1. 产品气质

MedPath 的高级感不来自炫技，而来自“科研可信度 + 新手友好 + 教学温度 + 工作流确定性”。

### 1.1 关键词

- 可信：每个建议都有边界、来源、审查动作和人工复核出口。
- 温和：对科研小白不制造压迫感，用清楚语言解释“何时用、怎么用、不能怎么用”。
- 专业：方法、图谱、文章、模型调用都按结构化字段展示，减少泛泛而谈。
- 有生命力：桌宠、3D 小岛、滚动叙事和任务进度让学习过程有陪伴感，但不削弱科研严肃性。
- 可迁移：网页、Figma、移动端和静态演示包使用同一套内容骨架和组件语义。

### 1.2 视觉方向

推荐方向是“医学科研工作台 + 轻量艺术化学习空间”。

- 主工作区保持白底、清晰层级、高对比文本和克制色彩。
- 首页、方法家族页、文章工坊、绘图室和 3D 小岛可加入轻量插画、示意图、实验台、路径、岛屿、切片、星空笔触等隐喻。
- 统计图、证据图、方法示例图不得使用生成式图像伪造科研结果；只能使用合成教学数据、公开许可数据或明确标注的重绘示例。
- 不做廉价 AI 渐变背景，不堆叠重复玻璃卡片，不让装饰压过内容。

## 2. 总体设计原则

### 2.1 新手先行

任何入口都先回答科研小白最关心的四个问题：

1. 我现在应该点哪里？
2. 这个方法、图谱或文章流程解决什么问题？
3. 我需要准备什么数据或材料？
4. 哪些结果必须交给导师、教师或专家复核？

页面文案避免只写专业名词。每个专业模块都应有一句“给新手的话”，再进入正式字段。

### 2.2 严肃任务优先

装饰、动效和游戏化入口只服务任务，不制造额外认知负担。

- 方法详情页要让用户能判断“是否适合我的研究问题”。
- 文章工作流要让用户知道“下一步要补什么材料”。
- 科研绘图室要让用户先审字段，再选图，再生成 R/ggplot2 代码或提示词。
- 3D 科研小岛是学习入口，不是替代正式工作台的主要处理空间。
- 手机端 App 是科研任务伴侣，不是桌面端后台的压缩版。

### 2.3 内容唯一化

禁止所有详情页共用一套空泛模板。每个方法、文章流程、图谱、工具和小岛建筑都必须有独立内容。

唯一化至少体现在：

- 独立标题和一句话新手解释。
- 独立适用场景和不适用场景。
- 独立输入、输出、风险和导师复核问题。
- 独立示例图或示意图。
- 独立来源线索、公开数据说明或合成教学边界。
- 独立 Skill 调用链或模型网关提示词。

### 2.4 可审查边界

所有 AI、教学示例、开源来源和模型输出都必须显示边界：

- 教学与科研训练用途，不替代临床诊断。
- 不处理真实可识别患者隐私。
- 不复制论文原图，不伪造真实研究结论。
- 模型输出必须保留人工复核问题。
- API Key、私有数据和授权课程材料不得进入截图、文档、日志或公开仓库。

## 3. 信息架构

### 3.1 桌面端主结构

桌面端是严肃科研工作台，推荐保留左侧导航 + 顶部任务输入 + 主内容长页结构。

主要分区：

1. 首页 / Researcher：科研小白入口、今日任务、路径生成、继续上次任务。
2. 方法库 / Method Universe：方法分类、方法家族、方法详情、需求生成。
3. 文章工坊 / Article Workshop：文章类型、从 0 到 1 流程、任务包、审稿前检查。
4. 科研绘图室 / Plot Studio & Gallery：图谱分类、字段审查、示例图、R/ggplot2 脚本建议。
5. 数据门诊 / Data Audit：上传或粘贴字段后做格式、统计适配和伦理边界审查。
6. 模型驿站 / Model Gateway：用户自有 API 配置、请求包规范、安全提示和 mock 模式说明。
7. 3D 科研小岛 / Research Island：游戏化学习地图和正式功能入口。
8. 我的任务 / Review：收藏、运行记录、导师复核清单、导出记录。

### 3.2 页面层级

每个核心页面采用四层结构：

1. 入口层：一句话说明当前页面帮助用户完成什么。
2. 决策层：搜索、筛选、任务输入、推荐路径或分类入口。
3. 工作层：卡片列表、流程步骤、表单、图谱建议、任务包生成。
4. 复核层：来源、风险、边界、导师问题、导出或进入下一步。

## 4. 卡片规范

卡片不是装饰容器，而是可比较、可选择、可继续的任务单元。

### 4.1 方法卡片

必须包含：

- 方法名称：中文名 + 英文名或缩写。
- 解决问题：一句话说明适合回答什么科研问题。
- 输入材料：数据、样本、实验条件或文献材料。
- 输出结果：图、表、模型、统计量、流程或报告。
- 新手风险：一个最常见误区。
- 状态：示例数据可跑、用户数据可跑、仅学习参考、待接入。
- 下一步：查看详情、生成任务包、加入复核清单。

### 4.2 文章流程卡片

必须包含：

- 文章类型：Meta 分析、系统综述、单细胞、病理 AI、机制研究等。
- 从 0 开始的第一步。
- 必备材料清单。
- 关键质量标准：如 PRISMA、风险偏倚、统计方案、数据字典等。
- 交付物：提纲、检索式、图表清单、方法段落、投稿前检查表。
- 导师复核点。

### 4.3 图谱卡片

必须包含：

- 图谱名称和适合回答的问题。
- 数据字段要求。
- 不适合绘制的情况。
- 示例图缩略图。
- 推荐工具：优先 R/ggplot2；交互图再考虑 Plotly、ECharts 或 D3。
- 字段审查入口。
- 合成示例或公开数据来源说明。

### 4.4 小岛建筑卡片

每个建筑是一个功能入口，不是纯装饰。必须包含：

- 建筑名。
- 任务目标。
- 三步路径。
- Skill 调用链。
- 证据或材料要求。
- 奖励提示。
- 安全边界。
- 进入正式页面的按钮。

## 5. 详情页唯一化写法

详情页采用“产品式 Hero + 决策摘要 + 示例图 + 滚动解释 + 来源与复核 + 需求实验室”的固定骨架，但每个条目的内容必须不同。

### 5.1 标准骨架

1. Hero 区：
   - 类别标签。
   - 标题。
   - 给科研小白的一句话解释。
   - 场景故事：用户什么时候会需要它。
   - 两个操作：生成任务包、加入复核清单。
   - 右侧独立示例图或流程示意。

2. 决策摘要：
   - 适合什么问题。
   - 不适合什么问题。
   - 需要什么输入。
   - 输出什么结果。
   - 最容易出错的地方。

3. 示例与数据边界：
   - 示例图标题。
   - 图如何阅读。
   - 数据来源或合成教学说明。
   - 许可、复用和不可声称内容。

4. 工作流：
   - 准备材料。
   - 数据或文献审查。
   - 方法执行。
   - 图表与结果解释。
   - 人工复核。
   - 导出或进入下一步。

5. 需求实验室：
   - 用户输入自然语言需求。
   - 平台生成结构化任务包。
   - 输出 Skill 调用链、字段清单、模型网关提示词和导师复核问题。

### 5.2 唯一化写作规则

禁止：

- 所有页面共用“这是一个重要方法，可帮助科研分析”这类空话。
- 所有页面使用同一张抽象装饰图。
- 所有卡片只改标题不改内容。
- 把公开来源线索写成真实研究证据。

必须：

- 方法详情写出具体适用数据，例如 bulk RNA-seq、single-cell matrix、WSI tile、GWAS summary statistics、clinical cohort。
- 图谱详情写出字段契约，例如 sample_id、group、value、gene、p_value、hazard_ratio、lower_ci、upper_ci。
- 文章流程写出真实工作流节点，例如 PICO、检索式、去重、全文筛选、数据提取、风险偏倚、GRADE、投稿检查。
- 工具详情写出输入输出和使用边界，例如 cBioPortal、Ensembl、PubMed、ChEMBL 等只作为公开线索，不替代原始数据核对。

## 6. Apple 式滚动产品页

Apple 式不是复制 Apple 视觉，而是借鉴它的“单屏单观点、节奏明确、内容逐步揭示”的产品叙事方式。

### 6.1 适用页面

- 首页的产品介绍区。
- 方法家族页。
- 单个方法、图谱或文章流程详情页。
- 3D 科研小岛介绍页。
- 手机端 App 发布或 Figma 交付说明页。

### 6.2 滚动结构

推荐每个长页包含 5 到 7 个 scroll panel：

1. 问题出现：用户正在面对什么科研困惑。
2. 方法选择：MedPath 如何把自然语言需求拆成方法、数据、图表和复核问题。
3. 数据准备：需要什么字段、样本、文献或实验条件。
4. 示例结果：如何读图、读流程或读输出。
5. 风险边界：哪些地方必须人工复核。
6. 下一步：生成任务包、进入绘图室、进入文章工坊或保存到手机端。
7. 导出与审查：可复制提示词、复核清单、图表清单或 Markdown/Word/LaTeX 骨架。

### 6.3 交互规则

- 每屏只表达一个主观点，避免一屏塞满多个卡片网格。
- 滚动时可以让示例图、流程线或任务面板轻微进入视野，但不能遮挡正文。
- 文本固定在安全阅读宽度内，桌面端每行不超过约 32 到 42 个中文字。
- 重要 CTA 不随滚动丢失，长页底部要再次出现“生成任务包 / 加入复核清单”。
- 减少纯装饰 parallax；动效必须解释层级、进度或状态。

## 7. 科研绘图室规范

科研绘图室的目标不是“炫图”，而是帮助用户先判断数据能不能画，再选择合适图谱。

### 7.1 工作流

1. 用户输入研究问题或粘贴字段名。
2. 数据门诊检查字段、缺失、分组、数值类型、统计适配和伦理边界。
3. 平台推荐可绘制图谱和不可绘制图谱。
4. 用户进入图谱详情，查看字段契约和示例图。
5. 平台生成 R/ggplot2 优先的代码建议，复杂交互图再给出前端图表库建议。
6. 用户保存图表计划、导师复核问题和数据修复建议。

### 7.2 视觉规则

- 图谱缩略图必须真实反映图类型，不使用抽象装饰替代。
- 示例图要标注“合成教学数据”或公开来源。
- 图谱详情页应显示字段契约表，而不是只放一段说明文字。
- 颜色用于表达分组、显著性、风险或状态，不随意装饰。
- 错误、缺字段、不适合绘制的情况要比成功态更清楚。

## 8. 文章工作流规范

文章工坊面向“从 0 到 1 搭流程”，不要像普通博客分类页。

### 8.1 文章流程页结构

- 文章类型定位。
- 适用研究问题。
- 必备材料。
- 从 0 开始流程图。
- 每一步需要的输入。
- 每一步输出的文档或表格。
- 常见退稿风险。
- AI 可辅助内容和禁止替代内容。
- 质量标准和导师复核问题。
- 导出：Markdown、Word、LaTeX、图表清单、投稿前检查表。

### 8.2 Meta 分析重点规则

Meta 分析流程必须显式显示：

- PICO。
- 检索数据库和检索式。
- 去重和筛选。
- 数据提取表。
- 风险偏倚。
- 效应量和异质性。
- 亚组和敏感性分析。
- 森林图、漏斗图、PRISMA 流程图。
- GRADE 或证据质量。
- 投稿前检查。

## 9. 3D 科研小岛规范

3D 科研小岛是“游戏化学习入口 + 功能地图”，不是把所有严肃任务塞进 3D 场景。

### 9.1 场景设计

推荐建筑：

- 方法图书馆：进入方法库和方法家族。
- 科研绘图室：进入图谱分类、字段审查和绘图计划。
- 文章工坊：进入文章工作流。
- 数据门诊：进入数据审查。
- 模型驿站：进入模型网关和 mock 输出说明。
- 伦理门岗：进入 AI 输出风险检查。
- 导师小屋：生成新手学习路径和复核清单。
- 成果邮局：导出任务包、图表清单和写作骨架。

### 9.2 交互规则

- 点击建筑后角色移动或镜头轻微转向，右侧任务面板展开。
- 任务面板必须解释“这个入口解决什么问题”，并给出进入正式页面的按钮。
- 建筑亮起代表任务进展，不代表真实科研完成。
- 不在 3D 场景中展示真实患者数据、真实模型结果或不可公开材料。
- 移动端可提供简化 2D 岛屿地图，不强制运行完整 3D。

### 9.3 性能和可访问性

- 3D 场景必须有非 3D 替代入口。
- 低性能设备显示静态岛屿图 + 功能列表。
- 所有建筑操作可通过键盘或列表按钮触发。
- 提供“减少动效”模式。

## 10. 手机端 App 规范

手机端定位为 MedPath Research Companion 的轻量任务伴侣。

它不复制桌面端复杂后台，而是支持：

- 快速输入一句科研需求。
- 查方法、图谱和文章流程。
- 保存任务、收藏方法和生成复核清单。
- 查看示例图和字段要求。
- 接收安全边界和导师复核提醒。
- 把复杂数据处理交回桌面端。

### 10.1 底部导航

推荐 5 个 tab：

1. 今日：任务、继续上次、快速输入、安全提醒。
2. 方法：方法搜索、方法家族、收藏方法。
3. 绘图：图谱搜索、字段审查、示例图。
4. 文章：文章类型、从 0 到 1 流程、进度。
5. 我的：复核清单、导出记录、设置和隐私。

如需保留小岛，可放在首页入口或“我的”中的学习模式，不占用第一版底部核心 tab。

### 10.2 移动页面规则

- 首屏只给一个主要行动，例如“输入你的研究问题”。
- 卡片短而明确，避免桌面端字段完整搬运。
- 详情页采用折叠分段：简介、适用场景、输入输出、示例图、复核问题。
- 表格转为字段列表或横向可滚动区域。
- 复杂图只显示可读缩略图，点击后进入全屏查看。
- 所有主要触控目标不小于 44 x 44 px。

## 11. Figma 移动端交付路线

Figma 交付不只是画静态页面，而是建立可维护的移动端设计系统。

### 11.1 交付顺序

第一阶段：设计基础

- 颜色变量：背景、文本、状态、医学绿、科研蓝、提醒黄、风险红。
- 字体样式：页面标题、分区标题、正文、标签、说明、代码或字段。
- 间距变量：4、8、12、16、24、32。
- 圆角变量：4、6、8、12。卡片默认不超过 8，移动端大容器可使用 12。
- 阴影变量：只用于浮层、底部 sheet、悬浮输入和关键卡片。

第二阶段：核心组件

- App shell。
- Bottom navigation。
- Search / command input。
- Method card。
- Plot card。
- Article workflow card。
- Detail hero。
- Field contract list。
- Review checklist。
- Source proof card。
- Safety notice。
- Bottom sheet。
- Toast / status message。

第三阶段：核心流程

- 启动页。
- 今日首页。
- 一句话研究路径。
- 方法分类。
- 方法详情。
- 绘图助手。
- 图谱详情。
- 文章工坊。
- Meta 分析流程。
- 复核清单。
- 设置与安全。

第四阶段：交互原型

- 从首页输入需求到生成路径。
- 从方法卡片进入详情并加入复核清单。
- 从字段审查进入图谱详情。
- 从文章类型进入流程步骤。
- 从复核清单导出给导师。

### 11.2 Figma 命名规则

- Page：`00 Foundations`、`01 Components`、`02 Mobile Flows`、`03 Desktop References`、`04 Prototype`。
- Frame：`Mobile/Home/Today`、`Mobile/Methods/List`、`Mobile/Methods/Detail`。
- Component：`Card/Method`、`Card/Plot`、`Notice/Safety`、`Input/ResearchPrompt`。
- Variant：使用 `state=default|active|disabled|warning`、`size=mobile|desktop`、`type=method|plot|article`。

### 11.3 交付验收

- 所有核心 frame 使用 Auto Layout。
- 颜色和文本样式来自变量，不手动散落。
- 组件有默认态、激活态、空态、错误态和加载态。
- 移动端至少检查 375 x 812、390 x 844、430 x 932 三种尺寸。
- 原型能跑通 3 条路径：找方法、选图谱、搭文章流程。

## 12. 动效规则

动效用于表达状态、层级和反馈，不用于炫耀。

### 12.1 允许动效

- 页面进入：内容轻微上移和淡入，150 到 240 ms。
- 卡片 hover：边框、阴影或背景轻微变化。
- 任务生成：进度条、步骤点亮、骨架屏。
- 详情页滚动：示例图和说明分段出现。
- 3D 小岛：建筑高亮、角色移动、任务面板展开。
- 手机端：bottom sheet、toast、tab 切换和按钮反馈。

### 12.2 禁止动效

- 高频闪烁。
- 大面积背景持续流动。
- 文本阅读区域 parallax 过重。
- 图表数据点无意义跳动。
- 强制自动轮播核心信息。
- 用动效掩盖加载失败或数据缺失。

### 12.3 减少动效模式

当用户系统开启 prefers-reduced-motion 或应用内开启减少动效时：

- 取消 parallax、长距离位移和连续旋转。
- 保留即时状态变化。
- 3D 小岛改为静态地图或低频镜头切换。

## 13. 可访问性规则

### 13.1 文本与对比

- 正文不小于 14 px，移动端正文建议 15 到 16 px。
- 主文本和背景对比达到 WCAG AA。
- 风险、成功、警告不能只靠颜色区分，必须有文本或图标。
- 不使用负字距。
- 中文段落控制行宽，避免长行阅读疲劳。

### 13.2 键盘和读屏

- 所有按钮、卡片行动、筛选器、tab 和弹窗可键盘访问。
- 焦点态清晰可见。
- 图表和示例图必须有 alt 文本或文字说明。
- 3D 小岛建筑必须有对应的列表入口和 aria-label。
- 模型输出、风险提示和错误信息要被读屏识别。

### 13.3 错误与空态

错误信息必须告诉用户：

- 哪里错了。
- 为什么影响结果。
- 怎么修复。
- 是否需要导师或专家复核。

空态不能只写“暂无数据”，应提供下一步：

- 输入研究问题。
- 粘贴字段名。
- 选择一个文章类型。
- 查看示例任务。
- 返回方法库。

## 14. 外部模式借鉴边界

本项目可以借鉴成熟设计产品和开源 UI 社区的模式，但必须遵守以下边界：

- 只借鉴信息架构、交互节奏、组件语义、动效原则和设计系统组织方式。
- 不复制外部库代码、商业模板、未核对 license 的组件源码或视觉素材。
- 不复制 Apple、Aceternity UI、Magic UI、shadcn block、Figma UI kit 等外部作品的具体布局、文案、图像、动画实现或品牌表达。
- 如未来引入第三方包，必须在文档记录包名、版本、license、用途和替代方案。
- 任何论文图、数据库截图、商业软件界面都不能直接作为站内示例图；需要使用合成教学示例、公开许可素材或自行重绘并标注来源边界。

## 15. 质量检查清单

每次视觉或交互升级后，至少检查：

- 首页是否让科研小白 10 秒内知道下一步。
- 方法、图谱、文章和工具详情页是否真正唯一化。
- 示例图是否标注合成教学或公开来源边界。
- 是否仍存在重复模板文案。
- 长页滚动是否一屏一个观点。
- 移动端是否没有把桌面后台硬塞进小屏。
- 3D 小岛是否有非 3D 替代入口。
- 动效是否可关闭或减少。
- 错误态、空态和加载态是否清楚。
- 可访问性是否覆盖键盘、读屏、对比度和触控目标。
- 外部模式借鉴是否只停留在模式层面，没有复制代码或素材。
