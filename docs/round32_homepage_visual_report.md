# Round32 首页视觉与新手导航修复记录

## 本轮目标

根据用户反馈，本轮不继续堆功能卡片，而是把首页从“功能目录”改成“科研新手任务工作台”。核心目标是让新手先理解自己要完成什么任务，再进入方法、图谱、文章、工具或伦理审查。

## 已完成修改

1. 修正 `README.md` 发布状态：当前项目已初始化为本地 Git 仓库，但尚未绑定 GitHub 远程地址，也未真实发布。
2. 在 `apps/web/static/app.js` 中新增首页任务画布：
   - `homeAtlasStage()`：展示“研究问题、数据与材料、方法选择、图表证据、文章流程、复核审计”六个任务节点。
   - `homeTriagePanel()`：面向新手提供“我只有一个想法、我已有数据表、我想写文章、我想看图”的分诊入口。
   - `homeCapabilityMap()`：将平台能力组织成七个中心，而不是重复功能卡片。
3. 更新首页首屏文字：
   - 从“看不懂方法名”改为“把科研新手的一句话，变成可复核的研究任务包”。
   - 入口文案强调“按用途解释、先看图再整理数据、文章流程、开源工具边界”。
4. 在 `apps/web/static/styles.css` 追加 Round32 视觉层：
   - 首页 hero 使用更克制的实验台/任务画布视觉。
   - 右侧任务画布改为稳定的二维矩阵，避免绝对定位导致节点重叠。
   - 首页桌宠默认收缩为小入口，点击后再展开，避免遮挡内容。
5. 更新 `apps/web/index.html` 和 `apps/web/sw.js`：
   - 资源版本号升级到 `round32`。
   - Service Worker 缓存名升级到 `medpath-research-companion-v32`，避免旧样式缓存。

## 设计依据

- 参考 Apple 产品页的连续叙事思路：首屏先给任务转化主张，再给路径和能力中心。
- 参考 NN/g 信息架构原则：按用户心智模型组织入口，而不是按技术名词堆菜单。
- 参考开源设计系统实践：保持一致的按钮、面板、标签和安全边界，不复制外部代码。
