# MedPath Research Companion 2.0 全量重构主目标

创建日期：2026-06-11  
适用范围：后续所有 MedPath Research Companion 网站、工程、设计、发布和验收任务。

## 1. 总目标

把现有 GitHub Pages 网站从“科研教育工具目录原型”升级为一个可长期迭代的双模式平台：

1. **Workbench Mode 专业工作台模式**：面向科研新手、医学学生、教师和研究者，提供方法学习、文章流程、开源工具、科研绘图、案例模板、AI Skills、模型接口和个人成长档案。
2. **Research Island 科研小岛模式**：面向学习兴趣和社区互动，提供可交互小岛、建筑绑定功能、对话框任务入口、积分、排行榜、好友拜访和 Skill 展示。

平台必须能公开访问、可点击、可持续发布到 GitHub Pages，并在每一轮开发后留下可审查证据。

## 2. 当前网站关键问题

1. 内容结构偏窄，过度集中在病理和少数科研方法。
2. “虚拟敲除/虚拟扰动”被放成顶层大类，分类逻辑错误。
3. 文案偏 AI 总结稿，缺少科研新手能直接理解的任务语言。
4. 页面示例不足，许多功能没有示例输入、输出、图、学习路径和风险提示。
5. 视觉设计不够成熟，主站不像高质量医疗科技工作台。
6. 移动端适配不够，应独立设计移动端信息流和底部导航。
7. 科研小岛不是用户想要的“空间化科研入口”，需要按低多边形/2.5D 游戏化机制重做。
8. 社区、个人主页、排行榜、好友、拜访、点赞、收藏和积分系统不足。
9. 许多卡片和小模块文案容易同质化，必须逐个写出真实差异。

## 3. 产品定位

### 一句话定位

MedPath Research Companion 是一个面向科研学习、医学教育和 AI Skill 创作的工作台与游戏化社区平台。

### 用户

- 科研新手：不知道方法怎么选、数据怎么整理、图怎么画、文章怎么搭流程。
- 医学生/研究生：需要从课程、案例、报告训练过渡到科研问题。
- 教师/导师：需要课程设计、教学案例、学生反馈和评价材料。
- 医学 AI / 生物信息学用户：需要工具导航、方法解释、示例流程和安全边界。
- Skill 创作者：希望把自己的方法、案例和工具封装成可展示、可运行、可被点赞的 Skill。

## 4. 新信息架构

### 主导航

1. Home 首页
2. Learn 学习与教学
3. Research 科研工作台
4. Skills Skills 市场
5. Cases 案例与模板
6. Tools 开源工具导航
7. Plot Studio 科研绘图工作室
8. Method Runner 方法运行器
9. Community 社区
10. Island 科研小岛模式
11. Profile 个人主页
12. Settings 设置

### Research 分类修正

“虚拟敲除/虚拟扰动”必须放在：

`Research -> 生物信息学 -> 单细胞 -> 扰动分析 / virtual perturbation`

不能作为一级主类。相关方法可以包括 GEARS、scGen、CPA/chemCPA、scGPT perturbation tutorial、scTenifoldKnk 等，但每个方法必须说明：用途、输入、输出、适用数据、风险、原始仓库/论文、是否可直接运行。

## 5. 内容建设标准

每个最小内容单元，包括 Skill、方法、工具、文章类型、绘图模板、案例模板、建筑、社区作品，都必须包含：

1. 简短标题；
2. 一句话解释；
3. 适合谁；
4. 解决什么问题；
5. 输入材料；
6. 输出结果；
7. 示例输入；
8. 示例输出；
9. 示例图或截图；
10. 推荐学习路径；
11. 推荐文章/仓库/数据来源；
12. 风险和不适用场景；
13. 是否 mock、示意、合成、公开数据或真实实测；
14. 下一步按钮。

严禁用同一段模板替换几个关键词后重复铺满页面。

## 6. 视觉与交互标准

### 主站风格

参考用户给出的医疗科技 Dashboard 图：深色侧边栏、暖白背景、柔和功能色、清晰组件、精致但不过度装饰。

关键词：专业、柔和、清楚、有温度、有科研感。

### 手机端

手机端必须独立设计：

- 底部 Tab：Home、Explore、Island、Community、Profile。
- 首屏不放长说明，直接放“今天想做什么”“继续上次任务”“推荐工具”“进入我的小岛”。
- 文字更短，按钮更大，卡片更清楚。
- 不允许横向溢出，不允许小字挤压。

### 科研小岛

科研小岛必须接近用户参考图中的低多边形/2.5D/轻 3D 小镇体验。MVP 至少需要：

1. 可交互岛屿地图；
2. 建筑可点击；
3. 建筑弹出对话框；
4. 建筑跳转功能页面；
5. 用户可以看到自己的积分、等级和建筑；
6. 可点赞或收藏小岛；
7. 可展示排行榜；
8. 建筑和功能的绑定关系由数据驱动。

## 8. 技术路线

优先在现有静态发布体系上迭代，保证 GitHub Pages 可访问。若后续需要完整后端，再拆出 API 服务。

当前建议：

- 前端：现有静态应用继续快速迭代，可逐步迁移为 Next.js/React 架构。
- 交互：小岛优先用 Three.js 或轻量 Canvas/SVG/CSS 低多边形方案。
- 数据：所有内容先用 JSON 数据驱动，避免硬编码。
- 图像：可使用自生成图像、免费素材或代码图。必须记录来源。
- 发布：每轮构建后推送到 `gh-pages`。

## 9. 每轮执行流程

1. 对照本文件和 README 检查本轮任务是否偏离。
2. 先修信息架构和文案，再做视觉。
3. 每次新增页面，都要同时考虑桌面端和移动端。
4. 每次新增 Skill/方法/工具，都要有示例、学习路径和风险边界。
5. 每次新增游戏化功能，都要能说明它如何帮助科研学习，而不是单纯装饰。
6. 构建静态包。
7. 本地预览。
8. 发布 GitHub Pages。
9. 记录本轮完成、限制和下一步。

## 10. 真实性与安全边界

- 不使用真实患者隐私信息。
- 不把合成案例写成真实病例。
- 不伪造教学效果、教师评分、学生问卷、论文、专利、软著或平台上线。
- 不保存或暴露 API Key、HPC 密码或账号。
- 医学 AI 输出仅用于教学与科研训练，不替代临床诊断，不用于真实患者处置。
