# Round 11 Android / PWA 路线说明

## 推荐路线

当前建议先采用 PWA 或 Android WebView 外壳路线，而不是立即重写原生 Android App。理由是当前平台已经以 FastAPI + 静态 SPA 方式运行，核心功能主要是页面、API、方法库、模型网关、审查和任务包生成，适合先快速封装为移动端可访问应用。

## 方案 A：PWA

适用场景：

- 申报展示；
- 课程组内部试用；
- 不需要上架应用商店；
- 快速迭代页面和方法库。

需要补充：

1. `manifest.webmanifest`；
2. App 图标；
3. 离线缓存策略；
4. HTTPS 部署；
5. 移动端启动页；
6. API 地址配置；
7. 隐私与安全声明。

## 方案 B：Android WebView

适用场景：

- 需要一个可安装 APK；
- 希望保留当前网页开发效率；
- 需要后续接入本机安全存储、扫码、文件选择等能力。

需要补充：

1. Android 项目外壳；
2. WebView 安全配置；
3. 网络权限；
4. API 地址设置页；
5. 密钥不写入源码，只进入本机安全存储；
6. 文件上传和下载权限；
7. 教学与科研训练边界弹窗。

## 方案 C：原生 Android

适用场景：

- 平台功能稳定；
- 页面交互和数据模型已定型；
- 需要长期运维、推送通知、离线数据库、本机模型或深度权限。

当前不建议直接进入此阶段，因为方法库、文章流程、图表规则和模型网关仍在快速迭代。

## 测试路线

后续若进入 Android WebView 或原生 App，应使用 Android 测试流程验证：

1. 首屏加载；
2. 方法详情页；
3. 文章工坊；
4. 绘图室字段审查；
5. 模型网关 mock 模式；
6. 安全边界弹窗；
7. 无真实患者数据；
8. 无明文 API Key；
9. 离线/弱网提示。
