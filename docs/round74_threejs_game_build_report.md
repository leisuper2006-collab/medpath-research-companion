# Round74 Three.js 科研小岛游戏化建设报告

日期：2026-06-11

## 用户反馈

用户指出 Round73 的科研小岛只是低保真入口，“这个什么也不算”。本轮因此不再继续做静态说明，而是直接建设可运行的 Three.js 低多边形交互游戏场景。

- `apps/web/index.html`

## 已实现的真实游戏功能

1. 使用 Three.js 渲染低多边形 3D 科研小岛。
2. 创建岛屿地形、河流、道路、桥、树木、建筑和玩家角色。
3. 建筑不是静态图片，而是 Three.js 中的可点击 3D 对象。
4. 点击建筑后：
   - 角色会向建筑移动；
   - 页面弹出建筑对话框；
   - 对话框提供进入对应功能页面的按钮；
   - 可将建筑设为常用并获得积分；
   - 可生成拜访请求。
5. 已内置首批建筑：
   - 文献图书馆；
   - 教学楼；
   - 病理室；
   - 实验楼；
   - 绘图工坊；
   - Skill 工坊；
   - 社区中心；
   - 档案馆。
6. 已加入基础游戏系统：
   - 积分；
   - 建筑商店；
   - 排行榜展示；
   - 拜访次数；
   - hover tooltip；
   - 本地 localStorage 状态。

## 仍然是 MVP 的边界

1. 当前为 Web 端 Three.js 原型，不是 Godot 独立游戏。
2. 当前建筑商店只完成兑换交互提示，尚未支持拖拽摆放。
3. 当前社区、拜访、排行榜为本地演示数据，未接入真实账户系统。
4. 当前角色移动为自动路径趋近，不是完整 WASD/寻路系统。
5. 当前建筑模型由基础几何体生成，后续可替换为 Blender/Godot/GLTF 资产。

## 下一步

1. 将小岛从 8 栋建筑扩展到 20 栋建筑，并建立建筑库 JSON。
2. 增加角色点击地面移动和 WASD 控制。
3. 增加建筑拖拽摆放和地块编辑。
4. 增加好友小岛数据结构。
5. 增加真实排行榜、点赞、收藏和访问记录。
6. 如需更强游戏表现，可用 Blender/Godot 制作 GLTF 资产后导入 Three.js。

## 安全边界

本游戏页面不读取真实患者数据，不连接真实模型 API，不提交 HPC 作业。医学 AI 输出仅用于教学与科研训练，不替代临床诊断。
