# Round 11 产品建设总纲：MedPath Research Companion

## 0. 本轮目标理解

本轮目标不是继续微调旧页面，而是把 MedPath 从“能点开的科研教育平台原型”升级为面向科研小白、教师、研究生和医学AI课程团队的完整产品体系。用户希望平台同时具备严肃科研工具能力与游戏化学习吸引力，并能最终发布到 GitHub 仓库和公网网站，形成可演示、可传播、可持续建设的项目。

本轮拆成两条主线：

1. **严肃科研工作台主线**：几百种科研方法库、方法家族详情页、文章类型Skill、科研绘图工作室、数据审查、模型API接入、规范化输出、GitHub发布。
2. **游戏化学习与移动端主线**：梵高/医学艺术风视觉系统、桌宠入口、3D动物之森式科研岛、交互式小游戏、Figma手机端App、后续Android测试路线。

硬边界：

- 不伪造真实模型调用、真实课程试点、真实教师评分、真实论文或专利成果。
- 示例图可以使用开源数据或合成数据，但必须标注来源、许可和用途；若未核对许可，标注“待核对”。
- 医学AI输出仅用于教学与科研训练，不替代临床诊断，不用于真实患者处置。
- API Key 只来自用户本地环境变量，不进入代码、README、截图、日志或申请书。
- 游戏化与美术风格是交互入口，不弱化严肃科研方法的准确性和可复核性。

## 1. 产品重新定位

建议产品名：

**MedPath Research Companion**

中文名：

**MedPath科研入门与AI技能平台**

一句话定位：

面向基础医学、病理学、医学AI与生命科学科研新手，提供“方法百科、文章工作流、科研绘图、AI Skills调度、数据审查、伦理治理、游戏化学习和移动端任务管理”的一体化平台。

## 2. 网站信息架构

### 2.1 主导航

1. 首页：任务入口、科研小白路线、平台状态。
2. 方法宇宙：几百种科研方法，按研究目的和数据类型分类。
3. 方法家族页：例如“基因敲除/扰动”，展示十几种方法、功能、输入、输出、示例图和推荐文章。
4. 文章工坊：Meta分析、综述、机制研究、单细胞文章、病理AI文章等20+文章类型，从0搭流程。
5. 绘图工作室：火山图、热图、森林图、UMAP、Sankey、Chord、Kaplan-Meier等大量图种。
6. 数据审查：用户上传或粘贴数据后，先检查格式、缺失、列名、分组、统计适配性。
7. Skill插件中心：每个方法、文章、图表、审计任务都能转成标准Skill。
8. 模型API网关：接入用户自己的大模型API，按Skill规范输出。
9. 科研岛游戏模式：3D学习空间、桌宠、任务NPC、小游戏式入门。
10. 移动端App：Figma原型与后续Android测试路线。

### 2.2 首页必须回答的5个问题

1. 我是科研小白，我应该点哪里？
2. 我想做某类实验/分析，有哪些方法？
3. 我想写某类文章，从0开始要怎么做？
4. 我有数据，能不能先帮我检查能画什么图？
5. 我想调用自己的模型API，平台如何规范化输出？

## 3. 方法宇宙：几百种方法库

### 3.1 方法页标准字段

每一个方法详情页必须包含：

- 方法中文名；
- 英文名/缩写；
- 所属方法家族；
- 适合解决的问题；
- 不适合解决的问题；
- 需要的输入数据；
- 输出结果；
- 示例图；
- 示例数据来源；
- 新手解释；
- 典型工作流；
- 常见误区；
- 推荐学习路径；
- 推荐文章/教程；
- 可调用的Skill；
- 可运行状态：示例数据可跑 / 用户数据可跑 / 仅学习参考 / 待接入；
- 风险与伦理边界；
- 相关开源工具；
- 下一步推荐。

### 3.2 方法分类总表

第一批建议覆盖至少 12 大类，目标 300-500 个方法条目。

1. 基因扰动与功能验证；
2. 单细胞组学；
3. 空间组学；
4. 转录组与差异表达；
5. 蛋白组/代谢组；
6. 多组学整合；
7. 病理图像AI；
8. 医学影像AI；
9. 机制网络与通路；
10. 预后/诊断模型；
11. 药物反应与靶点预测；
12. Meta分析与证据医学；
13. 统计建模与机器学习；
14. 科研绘图与可视化；
15. RAG/知识图谱/文献智能体；
16. 论文写作与投稿审查。

### 3.3 示例：基因敲除/扰动方法家族

当用户搜索“我想做基因敲除”时，不应只给一个方法，而应列出方法家族：

1. CRISPR-Cas9 knockout；
2. CRISPRi；
3. CRISPRa；
4. shRNA knockdown；
5. siRNA transient knockdown；
6. conditional knockout；
7. Cre-LoxP system；
8. base editing；
9. prime editing；
10. transposon mutagenesis；
11. saturation mutagenesis；
12. pooled CRISPR screen；
13. arrayed CRISPR screen；
14. Perturb-seq；
15. CROP-seq；
16. CRISPResso/amplicon editing analysis；
17. GUIDE-seq/off-target detection；
18. rescue experiment；
19. overexpression complementation；
20. drug perturbation alternative。

每个方法都应显示：

- 它是“敲除、敲低、激活、编辑、筛选、验证”中的哪一种；
- 适合细胞系、动物模型、类器官还是单细胞扰动；
- 需要哪些数据和实验条件；
- 能产生什么结果；
- 常见失败点；
- 对应图：编辑效率图、表达变化图、筛选火山图、UMAP扰动图、通路富集图等。

### 4.3 Meta分析Skill示例

Meta分析Skill应从0开始支持：

- 明确PICO问题；
- 建立检索式；
- 选择数据库；
- 去重；
- 标题摘要筛选；
- 全文筛选；
- 数据提取表；
- 风险偏倚评价；
- 效应量选择；
- 异质性分析；

## 5. 科研绘图工作室

### 5.1 图类型扩展

首批至少支持 80+ 图类型。优先按科研问题分类，而不是按软件分类。

1. 差异分析：火山图、MA图、曼哈顿图、条形显著性图；
2. 表达模式：热图、聚类热图、DotPlot、FeaturePlot、RidgePlot；
3. 单细胞：UMAP、t-SNE、cell composition、marker bubble、trajectory；
4. 空间组学：spatial feature map、邻域图、空间通讯图；
5. 富集分析：气泡图、条形图、GSEA曲线、cnetplot、emapplot；
6. 生存分析：Kaplan-Meier、森林图、nomogram、校准曲线、DCA；
7. Meta分析：森林图、漏斗图、PRISMA流程图、risk-of-bias图；
8. 网络：PPI网络、调控网络、Sankey、Chord、Alluvial；
9. 机器学习：ROC、PR曲线、混淆矩阵、SHAP、特征重要性；
10. 病理图像：tile overview、attention heatmap、mask overlay；
11. 教学图示：流程图、技术路线图、任务链图、评价rubric图。

### 5.2 示例数据策略

用户希望“示例图就是这个方法跑出来的图”。建议三层数据：

1. 合成示例数据：立即可跑，安全无隐私；
2. 开源数据：选一个明确license/来源的数据集做演示；
3. 用户数据：上传后先做格式审查，再生成R/Python命令。

绘图优先使用 R/ggplot2，符合本工作区偏好；复杂交互图再用Plotly/ECharts/D3。

### 5.3 数据审查服务

绘图前必须先做数据审查：

- 列名是否规范；
- 是否有分组列；
- 是否有数值列；
- 缺失值情况；
- 是否适合该图；
- 是否需要长宽表转换；
- 是否需要log转换；
- 是否存在重复样本；
- 是否缺少统计检验字段；
- 输出建议命令和修复示例。

若接入用户自己的大模型API，大模型只负责解释和生成建议，平台规则负责结构化审查，避免全靠模型臆测。

## 6. 美术方向与网站体验

### 6.1 视觉定位

用户明确希望网站“有审美与艺术风，不单调，不要AI风格化”。建议方向：

**医学科研 × 梵高式星空笔触 × 动物之森式温柔科研岛**

严肃工作台保持清晰专业；游戏模式和首页背景可加入艺术化视觉。

### 6.2 视觉元素

1. 梵高星空笔触作为柔和背景纹理；
2. 细胞、切片、星云、岛屿、路径作为隐喻；
3. 桌宠小人作为“科研向导”；
4. 每个方法家族有独立插画；
5. 图表工作室使用“画室/实验室”混合视觉；
6. 3D科研岛使用动物之森式低多边形、圆润、温暖、可点击交互。

注意：严肃图表、统计图、证据图不能用图像生成模型伪造；艺术背景、桌宠、3D角色、岛屿场景可以用生成图或手绘风资产。

## 7. 3D交互式游戏网页

### 7.1 游戏定位

名称建议：

**MedPath Research Island**

中文：

**科研小岛**

目标：让科研小白通过移动角色、点击建筑和NPC来完成学习任务。

### 7.2 场景设计

岛上建筑：

1. 方法图书馆：进入几百种方法百科；
2. 绘图画室：进入科研绘图工作室；
3. 文章工坊：选择Meta分析、综述等文章Skill；
4. 病理教室：生成PBL案例和报告训练；
5. 数据诊所：上传数据并做格式审查；
6. 模型驿站：配置自己的API；
7. 审计塔：伦理治理和风险审查；
8. 成果邮局：导出Word、Markdown、图表和投稿清单。

### 7.3 交互方式

- 点击地面角色移动；
- 点击建筑打开对应功能；
- 点击桌宠弹出对话框；
- 通过小游戏学习科研流程；
- 任务完成后获得“方法徽章”或“文章进度卡”；
- 严肃任务仍在标准工作台完成，游戏只是入口与学习层。

技术路线：

- Three.js 或 React Three Fiber；
- 低多边形岛屿模型；
- 简单点击移动；
- 对话框与任务面板使用HTML叠加；
- 首版先做静态岛屿 + 点击建筑弹窗；
- 第二版做角色移动和任务进度。

## 8. 桌宠入口

桌宠角色可以作为全站入口：

- 名称：Pathy / 小派 / 小切片；
- 功能：解释页面、推荐下一步、提醒安全边界、帮新手选择方法；
- 形式：右下角可收起小人；
- 点击后弹出“我想做什么？”；
- 可切换：严肃模式 / 游戏模式 / 新手模式。

## 9. 手机端App与Figma

### 9.1 手机端核心功能

手机端不应复刻所有复杂后台，而应做“任务与学习伴侣”：

1. 今日科研任务；
2. 方法百科查询；
3. 文章流程进度；
4. 图表类型查询；
5. Skill运行记录；
6. 教师/专家复核提醒；
7. 桌宠问答；
8. 安全与伦理提醒；
9. 收藏方法和工具；
10. 导出/分享到电脑端。

### 9.2 Figma交付物

建议制作：

- Mobile App 首页；
- 方法家族页；
- 方法详情页；
- 文章Skill流程页；
- 绘图助手页；
- 数据审查页；
- 桌宠对话页；
- 任务进度页；
- 设置与安全页。

### 9.3 Android路线

若做Android原型，建议分三步：

1. WebView/PWA封装：最快发布；
2. React Native/Expo：更像原生App；
3. 原生Android：适合后续深度设备能力。

当前优先建议 PWA + Figma + Android emulator QA，而不是立即重写原生Android。

- 方法宇宙；
- 文章工坊；
- 绘图工作室；

## 12. 需要用户确认的关键点

1. GitHub仓库名称和是否公开；
2. 是否允许迁移当前FastAPI静态页面到React/Vite或Next.js；
3. Figma创建文件使用哪个团队/账号；
4. 是否优先做PWA，还是立即做Android原生/Expo；
5. 是否允许使用图像生成模型制作艺术背景、桌宠、3D概念图；
6. 示例开源数据优先选择生命科学通用数据，还是病理/单细胞/Meta分析数据；
7. 是否有指定大模型API格式或继续使用当前Provider Gateway；
8. 网站发布优先使用 GitHub Pages、Vercel、Cloudflare Pages，还是自有服务器。

## 13. 下一步建议

建议下一轮先做 **Phase 1 + Phase 2的最小可见版本**：

1. 生成 300+ 方法分类数据；
2. 做“基因敲除/扰动方法家族页”作为模板；
3. 做“Meta分析文章Skill全流程页”作为模板；
4. 扩展科研绘图室到 80+ 图种；
5. 新增桌宠入口雏形；
6. 把页面视觉进一步从后台风格升级为“医学艺术工作室”风格。

这样既能让网站马上变丰富，又不会被3D游戏、移动端和部署这些大工程拖住。
