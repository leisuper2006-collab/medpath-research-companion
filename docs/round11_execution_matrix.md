# Round 11 执行矩阵

| 模块 | 用户目标 | 本地可立即完成 | 需要外部确认/资源 | 第一批交付 |
|---|---|---:|---|---|
| 方法宇宙 | 几百个方法，按用途分类，例如基因敲除下列出十几种方法 | 是 | 需要后续人工核对文献和工具版本 | `method_taxonomy_v1.json`、方法家族页 |
| 基因敲除/扰动家族 | 点击后了解所有功能、输入输出、示例图和推荐文章 | 是 | 示例数据来源和许可需核对 | `gene_perturbation_methods.json`、家族详情页 |
| 文章工坊 | 20+文章类型从0搭流程，接用户大模型API后按Skill输出 | 是 | 用户API Key、目标期刊/学校规范 | `article_skill_workflows.json`、Meta分析demo页 |
| 科研绘图室 | 多图种、示例案例、开源顶刊数据或示例数据、数据审查 | 部分 | 真实顶刊数据许可需核对；可先用公开/合成数据 | `plot_gallery_taxonomy.json`、R脚本、示例图 |
| 数据审查 | 数据不规范时提示如何修复，借助用户API解释 | 是 | 用户真实数据由用户本地提供 | `data_audit_rules.json`、前端审查页 |
| 模型API规范化输出 | 接入自己的大模型API，按Skill规范输出文章/图表/方法建议 | 是 | 用户配置API Key；不写入仓库 | Provider Gateway扩展、Skill输出schema |
| 网站审美升级 | 参考几十个热门网站，不单调、不AI模板化 | 是 | 可继续用图像生成模型做艺术资产 | 视觉系统、桌宠入口、艺术背景 |
| 桌宠 | 可爱小人，点击后作为网站入口/科研向导 | 是 | 角色形象可由用户选名或确认风格 | 桌宠组件、对话入口 |
| 3D游戏页 | 动物之森风科研小岛、可移动人物、点击建筑进入任务 | 部分 | 复杂3D资产需逐步制作 | Three.js首版：岛屿、建筑、点击弹窗 |
| Figma手机端App | 手机端完成上述功能的App设计 | 部分 | 需要Figma账号/plan选择 | Figma移动端页面设计或本地设计稿 |
| Android App | 用安卓插件做测试 | 部分 | 需要Android项目/模拟器环境 | PWA/WebView路线、后续emulator QA |
| GitHub发布 | 发布到用户仓库，别人能访问 | 部分 | 需要仓库名、是否公开、部署平台 | README、部署配置、发布路线 |

## 推荐实施顺序

### 第一步：先把内容底座做厚

1. 方法库扩到 300+。
2. 基因敲除/扰动方法家族做成模板。
3. 文章工坊做 24 类文章Skill。
4. 绘图室扩到 80+ 图类型。
5. 数据审查规则先做表格/CSV/R data.frame基础检查。

### 第二步：再把前端做成真正产品

1. 方法宇宙页。
2. 方法家族详情页。
3. 文章工坊页。
4. Meta分析全流程页。
5. 绘图工作室新界面。
6. 数据审查页。
7. 桌宠入口。

### 第三步：做艺术化和游戏化

1. 生成或制作梵高风医学科研背景。
2. 设计桌宠角色。
3. Three.js科研小岛。
4. 点击建筑进入方法/文章/绘图任务。
5. 加新手任务系统和徽章。

### 第四步：发布与移动端

1. 整理GitHub仓库。
2. 选择部署平台。
3. Figma移动端设计。
4. PWA/Android路线。

## 本轮不能直接声称完成的内容

- 不能声称已经接入用户真实大模型API，除非用户配置环境变量并授权测试。
- 不能声称已使用顶刊真实数据完成分析，除非确认数据许可并保留来源。
- 不能声称已发布公网网站，除非完成GitHub push和部署。
- 不能声称安卓App已上线，除非实际构建、安装和测试。
- 不能声称3D游戏已完整完成，首版应先做可点击原型。
