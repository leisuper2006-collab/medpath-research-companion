# MedPath 组件规范

本规范用于后续在 Figma 中重建 MedPath Research Companion 的可编辑设计母版。当前 Figma MCP 握手失败，尚未写入线上 Figma 文件；本目录提供可导入和可复刻的设计依据。

## 1. App Shell

用途：承载桌面端研究平台。

结构：

- 左侧固定导航：286px，分组显示“开始、教学与训练、插件与工具、运行与治理”。
- 顶部命令栏：当前页面搜索/任务输入/快速入口。
- 主内容区：最大宽度 1480px，支持详情页长滚动。

设计要点：

- 不是单调卡片墙，左侧导航应像科研工作台目录。
- 顶部命令栏像“科研任务输入口”，而不是普通搜索框。
- 主区域要有长页面节奏，避免重复三列卡片。

## 2. Product Detail Hero

用于方法、文章、图谱、开源工具四类详情页。

必备内容：

- 类别标签；
- 产品式标题；
- 新手导入语；
- 场景故事；
- 两个操作按钮；
- 右侧示例图框。

视觉规则：

- 左文右图，不使用花哨背景。
- 示例图必须有标题和来源边界。
- 文案要根据条目真实情况生成，不得所有页面相同。

## 3. Scroll Story Panels

用于 Apple 式产品介绍段落。

结构：

- 左上角编号 `01/02/03/04`；
- 小标题；
- 一段解释文字。

内容规则：

- 第一屏解释“什么时候用”；
- 第二屏解释“数据/材料是否够”；
- 第三屏解释“示例图或方法如何读”；
- 第四屏解释“人如何复核”。

## 4. Source Proof Card

用于公开来源线索和真实边界。

必备字段：

- 来源标题；
- 来源描述；
- 引用线索；
- PMID 或数据库入口；
- 许可/复用边界；
- 打开公开来源按钮。

禁止：

- 复制论文原图；
- 下载受控数据；
- 把公开来源线索写成已完成研究证据。

## 5. Demand Lab

用于“描述我的需求”窗口。

结构：

- 一组 starter prompt；
- 需求文本框；
- 生成规范化任务包按钮；
- 模型网关入口；
- 右侧结果框。

结果应包括：

- 任务目标；
- 输入清单；
- 执行路径；
- 推荐图表；
- Skill调用链；
- 数据审查；
- 导师复核问题；
- 可复制模型提示词。

## 6. Research Island

用于 3D 科研小岛。

建筑不是装饰，而是功能入口：

- 方法楼；
- 文章工坊；
- 绘图室；
- 数据审查室；
- 模型网关；
- 伦理治理站；
- 插件中心；
- 案例实验室。

交互规则：

- 点击建筑，小人移动；
- 右侧面板解释“这个入口解决什么问题”；
- 进入正式页面；
- 不连接真实患者数据。

## 7. Mobile App Bottom Navigation

建议五个 tab：

1. 首页；
2. 方法；
3. 绘图；
4. 文章；
5. 我的任务。

手机端优先场景：

- 新手用一句话生成研究路径；
- 点开方法详情；
- 查看示例图和数据字段；
- 生成模型提示词；
- 保存导师复核清单。
